## Key findings

- Spring Boot 4.1.1 supports Java 17–26, so Java 21 is inside the supported range.
- Spring Modulith 2.1.1 is compatible with Boot 4.1 and is used only for structure verification. An explicit GuideIn outbox remains necessary because GuideIn needs tenant-aware envelopes, deterministic leases, and future externalization; upstream multi-instance recovery discussions reinforce that choice.
- PostgreSQL table owners and `BYPASSRLS` roles bypass ordinary RLS. Therefore migrations own protected tables, while `guidein_app` is neither owner nor privileged; `FORCE ROW LEVEL SECURITY` remains defense in depth.
- `SKIP LOCKED` is intentionally inconsistent and appropriate only for queue-like claiming. Deterministic `ORDER BY available_at, id`, lease tokens, and guarded completion supply the missing domain semantics.
- OpenTelemetry's Java agent remains the default for broad Spring instrumentation. GuideIn keeps telemetry configuration outside application code and adds bounded Micrometer domain metrics without tenant-cardinality labels.
- Flyway's current database matrix explicitly includes PostgreSQL 18. PostgreSQL support is a separate Flyway module.
- Testcontainers has no special PostgreSQL 18 API requirement; the actual image version is explicit. Current upstream issues show Docker discovery/startup can fail independently of application correctness, so missing Docker is reported as an unexecuted gate, never a pass.

## Dependency decisions

Only Spring/Boot-managed dependencies, PostgreSQL JDBC/Flyway, Spring Modulith, Testcontainers, and the Apache-2.0 RFC 8785 implementation were added. Kafka, Redis, RabbitMQ, Neo4j, Debezium runtime, SpiceDB, an OTel starter, JPA/Hibernate, and a logging encoder were rejected or deferred.
